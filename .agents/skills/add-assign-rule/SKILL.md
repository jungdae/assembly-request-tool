# 배분 규칙 보강

> 사용법: 배분 엔진 시험 결과에서 틀린 문항을 보고, 사용자가 고른 보강 방법만 기준표 사본에 반영한다.
> 저장 위치: `.agents/skills/add-assign-rule/SKILL.md`
> 현재 상황: 원본 기준표는 그대로 두고 `rules_보강.csv`에 R136 `민원 서비스` 우선순위 3, R211 `안전등급` 우선순위 3, R181 `지방채` 우선순위 2를 반영했다. 그 결과 시험 40건 1순위는 27/40에서 30/40으로 올랐고, 새로 틀린 문항은 0건이었다.

## 1. 언제 쓰는지
- `web/engine.js`의 `classify(요구내용)` 결과가 시험 문항 또는 접수대장 정답과 맞지 않아 배분기준표를 보강할 때 쓴다.
- 사용자가 “이 키워드는 우선순위를 올려 줘”, “이 제외어를 추가해 줘”, “이 오답을 고쳐 줘”처럼 보강 방법을 고르거나 지시했을 때 쓴다.
- 입력은 `data/배분기준표_소관키워드_304건.csv`, `data/A부_조직도_26개과.csv`, `data/시험_요구문항_40건.csv`, `data/요구자료_접수대장_2026국감_520건.csv`이다.
- 원본 기준표는 읽기 전용으로 두고, 사용자가 고른 수정만 `rules_보강.csv`에 반영한다.

## 2. 순서
1. `CONTEXT.md`, `PROGRESS.md`, `00_문제정의/problem.md`, `00_문제정의/design.md`를 먼저 읽어 범위와 금지사항을 확인한다.
2. `test_engine.js` 또는 같은 방식의 Node 검증으로 틀린 문항을 뽑고, 원인별로 묶는다. 예: 넓은 키워드가 특정 소관 키워드보다 앞섬, 같은 키워드가 다른 과에 걸림, 제외어가 부족함, 우선순위가 낮음.
3. 원인마다 고칠 방법을 1개씩 제안한다. 방법은 제외어 추가, 키워드 추가, 우선순위 조정 중 하나로 쓰고, 새 규칙의 과는 반드시 조직도 26개 과 안에서만 고른다.
4. 사용자가 고른 방법만 `rules_보강.csv`에 반영한다. `rules_보강.csv`가 없으면 원본 기준표를 복사해 만들고, 있으면 기존 보강 내용을 보존한 채 이번 선택만 추가·수정한다. `data/배분기준표_소관키워드_304건.csv` 원본은 수정하지 않는다.
5. 고치기 전·후 정확도를 표로 비교한다. 기준은 시험 40건 1순위·3순위 안, 접수대장 520건 1순위, 새로 틀린 문항 수이다. 바꾼 규칙과 결과는 `PROGRESS.md`에 적는다.

## 3. 끝나는 조건
- `rules_보강.csv`가 있고, 사용자가 고른 규칙만 반영되어 있다.
- 시험 40건과 접수대장 520건의 고치기 전·후 정확도 표를 보여 줬다.
- 새로 틀린 문항 수를 확인했다.
- `PROGRESS.md`에 바꾼 규칙, 시험 결과, 접수대장 결과, 남은 오답 또는 막힌 점을 적었다.
- 스킬 저장 조건이 걸린 경우, 시험 40건 1순위가 30건 이상이고 새로 틀린 문항이 0건인지 확인한다.

## 4. 하지 말 것
- 원본 `data/배분기준표_소관키워드_304건.csv`, 조직도 CSV, 시험 문항 CSV, 접수대장 CSV는 수정하지 않는다.
- 사용자가 고르지 않은 보강안을 임의로 `rules_보강.csv`에 반영하지 않는다.
- 조직도 26개 과에 없는 부서명을 만들거나 후보로 쓰지 않는다.
- 답변 내용 작성, 결재, 국회 제출 기능은 만들지 않는다.
